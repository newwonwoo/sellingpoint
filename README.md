# sellingpoint — 법원경매 낙찰가율 조회

법원 매각통계에서 소재지(시도·시군구)×기간별 용도별 매각가율(=낙찰가율)을 가져오는 React+Vite 앱.

## 실행
```
npm install
vercel dev        # 로컬(한국 IP) — WAF 안전. 엑셀 대량수집도 이걸로.
```

## 화면 구성 (탭)
가동중 화면을 건드리지 않으려고 탭으로 나눴다.

| 탭 | 내용 | 비고 |
|---|---|---|
| 낙찰가율 조회 | 주소조회 + 상세통계 + 엑셀 | 기존 화면 그대로 |
| 사건번호 실익 | 사건번호 → 감정가·선순위·예상낙찰가 | 한 건씩 |
| 엑셀 일괄분석 | 사건번호 엑셀 업로드 → 결과 엑셀 | 같은 계산을 여러 건에 |
| 역추적(진단) | 낙찰가율 역추적 | **평소 숨김** — 주소에 `#tools` 를 붙여야 탭이 보인다 |

역추적은 "평균 낙찰가율 74%"의 정체를 파려고 만든 진단 도구라 실무 화면에 상시 노출할
이유가 없다. 코드는 그대로 두고 화면에서만 숨겼다. 탭은 해시(`#case`, `#tools`)로
링크·북마크되고 뒤로가기도 따라간다.

## 기능
- 조회: 시도·시군구·기간 선택 → 용도별 매각가율 표(한글 라벨·정합성 체크·CSV).
- **엑셀 받기(구별)**: 시도 선택 시 그 시도의 구 전체를 순회해 xlsx 1개. 특정 구만 고르면 그 구만.
- **전국 엑셀(zip)**: 시도 미선택 시 17개 시도를 전부 순회 → 시도별 xlsx를 zip 하나로(탭 아닌 파일별). 강원/전북은 신코드(51/52) 자동 보정.
  특정 구를 고른 경우 그 구만. 파일명 `매각통계_{시도}_{startYM}_{endYM}.xlsx`.
- 기간 빠른 선택(최근 3/6/12개월·올해).
- **낙찰가율 역추적**: "평균 낙찰가율 74%"처럼 기간·산식이 안 밝혀진 값을 넣으면, 그 값이 나오는
  (지역 × 용도 × 기간 × 산식) 조합을 전부 찾아준다. 월별 통계를 한 번 받아두고 모든
  (시작월, 종료월) 조합을 로컬에서 계산하므로, 용도·목표값·오차를 바꿔도 재조회가 없다.
  산식 2종을 함께 본다 — **금액가중**(법원 공식 = 매각가합÷감정가합)과 **대분류 단순평균**
  (용도별 값을 구성비 무시하고 그냥 평균 내는 서비스가 실제로 있다).
  일치 구간이 없으면 종료월 × 기간 참고표를 대신 보여준다.
- **엑셀 일괄분석**: 사건번호 엑셀 업로드 → 매물별 37칼럼 결과 엑셀 다운로드. 아래 별도 절.

## 사건번호 실익 미리보기
사건번호를 넣으면 그 재산의 **법원 감정가**를 받아 해당 시군구·용도 낙찰가율(최근 1년)을 곱해
예상낙찰가를 낸다. 감정가를 법원이 이미 매겨놨으므로 시세 API가 필요 없다.

⚠ **응답 한 줄 = 목적물이지 경매 단위가 아니다.** 감정가·최저가·유찰횟수는 매물(`maemulSer`) 단위라
목적물마다 같은 값이 반복된다. 그대로 더하면 2018타경6939이 34줄 × 77.88억 = **2,647억**이 된다
(실제 77.88억). 그래서 매물로 묶고 금액은 한 번만, 면적은 목적물 합으로 만든다.

### 선순위 정보도 법원이 준다
`/pgj/pgj15B/selectAuctnCsSrchRslt.on` (사건상세)에 **매각물건명세서 핵심 3항목**이 들어 있다.
등기부를 떼지 않아도 인수 여부 판단의 근거가 나온다.

| 필드 | 뜻 |
|---|---|
| `tprtyRnkHypthcStngDts` | **최선순위 설정일자** — 이보다 먼저 전입한 임차인은 낙찰자가 인수 |
| `ndstrcRghCtt` | **인수권리** — 매각으로 소멸하지 않는 권리(보증금 인수 등) |
| `sprfcExstcDts` | 법정지상권 성립 여지 |
| `clmAmt` | 청구금액 (경매 신청 채권자) |
| `dstrtDemnLstprdYmd` | 배당요구종기 |
| `gdsDspslObjctLst[].aeeEvlAmt` | 목적물별 감정평가액 |
| `gdsDspslDxdyLst` | 기일별 최저가(저감 이력)·낙찰가 |

요청은 `{csNo, cortOfcCd, dspslGdsSeq}` 세 개뿐이고 `cortOfcCd`는 검색결과의 `boCd`,
`dspslGdsSeq`는 `maemulSer`다. ⚠ 응답에 사진 base64(`csPicLst`)가 들어 있어 크다 — 필요한 필드만 고른다.

예) 2024타경115858은 감정가 3.61억인데 인수보증금이 3.68억이라 9회 저감됐다.
이건 평균 낙찰가율로는 절대 설명이 안 되는 물건이고, 인수권리를 보여주면 바로 납득된다.

### 실익 판단
폭포수로 계산한다. 인수권리는 낙찰자가 떠안으므로 그만큼 낮게 응찰하고 배당에도 들어가지 않는다.

```
  예상낙찰가 (감정가 × 낙찰가율)
− 인수권리      ← 명세서 문장에서 금액 자동 추출, 수정 가능
− 집행비용      ← 입력
= 배당재원
− 선순위채권    ← 입력 (등기부)
= 우리 배당가능액
```

판정: 배당가능액 0 → **실익 없음** / 채권액 미달 → **일부 회수** / 채권액 이상 → **전액 회수 가능**.
회수액은 채권액 한도까지만 잡는다(초과분은 후순위 몫).

⚠ **등기부 제한물권 목록은 법원 공개 API에 없다.** 이해관계인 열람은 인증이 필요한 영역이다.
대신 매각물건명세서가 법원이 등기부를 분석해 "소멸/인수"로 정리한 결론이라 목록보다 직접적이다.
선순위채권 합계는 등기부를 보고 입력해야 한다.

### 조회되는 사건과 안 되는 사건

**기준은 하나다.** `searchControllerMain.on` 은 *지금 매각이 진행 중인 물건 목록*이지 사건
아카이브가 아니다. 그래서 조회되는 조건은 **"앞으로 잡힌 매각기일이 있는 부동산 매물이
그 사건에 있다"** 뿐이다.

종결된 사건은 기일 범위를 어떻게 줘도 안 나온다. 실측(2016타경5000, 종국 2016.07.26):

| 보낸 기일 범위 | 결과 |
|---|---|
| 오늘 ~ +10년 (앱 기본) | 0건 |
| 2016년 한 해 | 0건 |
| 2006 ~ 2036 전체 | 0건 |
| 종국 직전 한 달 | 0건 |
| 법원코드까지 지정 | 0건 |

그러니 0건에 대고 "사건번호를 확인하세요"라고 하면 **대개 틀린 말**이다. 사건은 멀쩡히 있고
종결됐을 뿐인 경우가 많다. 사건내역 API(`pgj15A`)는 종결 사건도 돌려주므로 이걸로 사유를 가른다.

| 사유 | 판정 근거 | 담당자가 할 일 |
|---|---|---|
| **종결된 사건** | 사건 있음 + `ultmtDvsCd ≠ "000"` | 끝난 사건. 실익분석 대상이 아니다 |
| **매각기일 없음** | 사건 있음 + `ultmtDvsCd = "000"` | 기일이 잡히면 조회된다. 집행정지·항고면 같이 표시 |
| **부동산 사건 아님** | 사건명이 자동차·선박·건설기계·유체동산 | 이 도구 대상이 아니다 |
| **사건번호 확인 필요** | 전국 어느 법원에도 없음 | **여기서만** 오타를 의심한다 |

종국 판정은 법원 화면 로직 그대로다 — `ultmtDvsCd` 가 `"000"` 이면 미종국, 아니면 종국.

> ⚠ 사건명 매칭에 `동산` 을 그냥 넣으면 **"부동산강제경매"가 통째로 걸린다**. 실제로 그렇게
> 났고, 부동산 사건을 "부동산 사건 아님"으로 안내했다. `유체동산` 으로 명시해야 한다.

#### 검색에 안 잡혀도 감정가는 끌어온다

사건내역의 `dlt_dspslGdsDspslObjctLst` 에 **매물별 감정가**(`aeeEvlAmt`)가 들어 있고,
이게 검색보다 넓다. 실측(서울중앙 미종국 부동산 13건):

| | 검색됨 | 검색 0건 |
|---|---|---|
| **감정가 있음** | 6건 | **7건** ← 이게 새로 살아난다 |
| 감정가 없음 | - | 34건 (감정평가 진행 전) |

절반 넘게가 *감정은 끝났는데 아직 공고 전*이라 검색에만 안 잡히던 것이다. 실익 판단의
출발점이 감정가라서, 이게 있으면 '조회 실패'가 아니라 **자료가 덜 찬 조회 성공**으로 다룬다.
같이 오는 것: 최초 최저가·매각기일(있으면)·시도/시군구 코드·주소·목적물 동호수.

⚠ **종결된 사건은 이 경로로도 못 살린다.** 종국 사건 26건 전부 이 데이터셋이 0건이었다
(종국 10일밖에 안 지난 건도 0건). 감정평가서 API도 본문을 안 주고(`ordTsCnt` 4가지 전부),
`selectGdsCmprsInf` · `selectPopUpGdsLstDts` 는 500/550 이다. 법원이 종국 사건은 기본사항만 준다.

⚠ **여기도 '한 줄 = 목적물'이다.** 매물에 목적물이 3개면 같은 감정가가 3줄 반복된다. 그대로
매물로 세면 2026타경100137이 10.7억짜리 매물 3건(=32억)으로 보인다. 실제로 그렇게 났다.
검색 경로에서 `maemulSer` 로 묶은 것과 같은 이유로 `dspslGdsSeq` 로 묶는다.

#### 중복경매(이중경매)는 모사건에 감정가가 있다

같은 부동산에 경매가 겹쳐 들어오면 감정평가는 먼저 들어온 사건(**모사건**)에서만 한다.
자식 사건은 감정가가 통째로 비어 있고, 사건내역의 `dlt_dpcnMrgTrnscsCsRlet` 가 모사건을 가리킨다
(`userReltCsNo` + `reltCortOfcCd`). 그 사건을 한 번 더 조회하면 감정가가 나온다.

> 실측: 2026타경100115 ← 2024타경124852 (반포자이, 49.6억) / 2026타경100137 ← 2024타경2099 (10.7억)

⚠ **다른 사건번호의 값이므로 반드시 출처를 밝힌다.** 화면 배너와 엑셀 `특이사항` 에
"중복경매 — 감정가·소재지는 모사건 ○○○의 값" 이라고 적는다. 조용히 갖다 쓰면 숫자를 믿을 수 없게 된다.

#### 감정가 수집률 (실측)

서울중앙·서울남부의 2026타경 **연속 번호대 280개**를 훑어 실재 사건 140건으로 계산했다.

| 사건 상태 | 건수 | |
|---|---|---|
| 종결 | 53건 (38%) | 법원이 감정가 비공개 |
| 부동산 아님 | 4건 (3%) | 자동차·선박 |
| 미종국 · 검색됨 | 32건 (23%) | 기존 경로 |
| 미종국 · 검색X 감정O | 11건 (8%) | **사건내역에서 확보** |
| 미종국 · 중복경매 | 5건 (4%) | **모사건에서 확보** |
| 미종국 · 감정 전 | 35건 (25%) | 법원에도 아직 없다(감정평가서도 없음) |

**부동산 진행 사건 83건 기준 감정가 수집률: 검색만 39% → 사건내역 52% → 모사건까지 58%.**
남은 42%는 전부 '아직 감정평가를 안 한 사건'이라 법원에서도 가져올 수 없다.

⚠ **없는 값을 0으로 채우지 않는다.** 면적·유찰횟수가 없는데 0을 넣으면 "유찰 0회"라는
거짓말이 된다. `null` 로 두고 화면·엑셀에 `-` 로 표시한다.

⚠ **용도 코드는 쓰지 않는다.** 3단계 코드(`20000/20100/20104`)로만 오는데, 검색 결과와
짝지어 332건을 수확해 코드→이름 표를 만들어 보니 `20104` 하나가 아파트·다세대·오피스텔·
상가에 모두 걸릴 만큼 충돌이 심했다. 억지로 매핑하면 엉뚱한 낙찰가율이 붙는다.
용도를 비워 그 시군구 **전체** 낙찰가율로 떨어뜨리고, 화면·엑셀에 그 사실을 표시한다.

화면은 배너로, 엑셀은 `특이사항` 칼럼으로 *"매각물건 검색 미노출 — 사건내역의 감정가로 계산"*
이라고 밝힌다. 어디서 온 값인지 모르면 쓸 수 없는 숫자다.

**법원코드가 필수다.** 사건내역은 `cortOfcCd` 없이는 아무것도 안 준다(빈 값·부분 값 모두).
검색이 실패해 법원을 모르므로 전 법원(51곳)을 10곳씩 병렬로 훑고 먼저 걸리면 멈춘다.
실측 최악 1.6초(전부 훑음), 보통 0.3~1초.

법원코드 목록은 매각기일별 검색에 `cortOfcCd` 를 넣어 `B000200~B000799` 를 훑어 얻었다(51곳).
⚠ *지금 진행 물건이 있는 법원*만 잡히므로 물건이 하나도 없는 지원은 빠질 수 있다.
⚠ 훑을 때 `pageSize` 는 반드시 `40` 이다 — `1` 을 주면 서버가 전부 0건으로 돌려준다.

### ⚠ 사건번호 검색은 기일 범위를 같이 보내야 한다
`csNo` 만 보내면 서버가 **공고 게시 중인 임박 기일**로 범위를 좁혀버려 사건이 멀쩡히 있는데도
0건이 온다. 실측으로 매각기일까지 D-10 이내는 조회되고 D-16 이상은 안 됐다(법원마다 편차가 있고,
서울동부는 같은 D-22에서 하나는 되고 하나는 안 됐다 — 날짜만으로 결정되지는 않는다).

`bidBgngYmd`~`bidEndYmd` 를 넓게(오늘~+10년) 주면 해결된다. 0건이던 4개 사건이 전부 조회되고
되던 사건들도 결과가 같다(7/7). 과거 기일만 있는 사건(종결·취하)은 어떤 범위로도 0건이다.

### 매각물건명세서 공개 시점
명세서는 **매각기일이 가까워야 공개**된다(뷰어 XML에 `MseoViewDate = 7` 주석).
공개 전이면 사건상세(`selectAuctnCsSrchRslt`)가 `dma_result: {}` 를 준다 — 실측 D-16 공개 / D-18 미공개.
이때 선순위·청구금액을 조용히 비우지 말고 `detailReady: false` 로 표시해 화면에서 안내한다.
감정가·최저가·유찰횟수는 목록에서 오므로 이 경우에도 정상이다.

#### ⚠ 임차인은 매물별로 갈라야 한다
현황조사서는 **사건 단위**로 오고 임차인은 `objctSeq`(목적물)에 묶여 있다. 매물이 여럿인 사건에서
전체 임차인을 모든 매물에 그대로 뿌리면, 남의 물건 임차인이 이 매물의 최선순위와 비교돼 '인수'로
잡힌다 — 그만큼 실익 판정이 틀어진다. `scopeTenants`(`src/caseModel.js`)가 목적물 번호로 가른다.

목적물 번호가 비어 오거나 체계가 어긋나는 사건이 있다. 이때 임차인을 **숨기지 않는다** —
전부 보여주되 "이 매물 것이 아닐 수 있음"을 알린다. 위험 정보는 감추는 쪽이 아니라
표시하는 쪽으로 틀리는 게 맞다.

## 엑셀 일괄분석
사건번호가 적힌 엑셀을 올리면 사건마다 위 조회를 돌려 **매물 한 줄씩 37개 칼럼**으로 정리한
엑셀을 바로 내려받는다. 화면(한 건)과 **같은 계산 모듈**(`src/caseModel.js`)을 쓴다 —
화면 판정과 파일 판정이 다르면 그게 사고라서 일부러 한 소스로 묶었다.

**업로드** — `사건번호` 칼럼만 있으면 된다. `우리채권액`·`선순위채권`·`집행비용`·`인수권리금액`이
같이 있으면 실익 판정까지 채운다(칼럼 이름은 `채권액`·`선순위`·`경매비용` 같은 흔한 표기도 인식).
`관리번호`·`고객명` 등은 결과 첫 칼럼에 그대로 돌려줘 내부 시스템과 대사할 수 있다.
`"3억"`·`"368,000,000"` 같은 표기도 읽는다. 화면에서 **업로드 양식**을 받을 수 있다.

사건번호 칼럼을 못 찾으면 시트 전체를 훑어 사건번호만 주워 담는다. 이때는 **`타경`이 박힌 것만**
받는다 — 느슨하게 두면 전화번호 `02-1234-5678` 이 `1234타경5678` 로, 사업자번호 `1234567890` 이
`1234타경567890` 으로 둔갑한다(실제로 테스트에서 났다). 앞 4자리 연도 검사도 같은 이유로 넣었다.

**결과** — 시트 2개. `실익분석`(37칼럼, 자동필터, 실익판정 색상)과 `분석조건`(기준기간·건수 +
"이 값은 왜 0인가"를 적어둔 주의사항). 조회되지 않은 사건도 한 줄 남기고, `실익판정` 칸에 **사유를 그대로 찍는다**
(`종결된 사건` / `매각기일 없음` / `부동산 사건 아님` / `사건번호 확인 필요`).
전부 "조회 실패"로 뭉뚱그리면 담당자가 다시 한 건씩 봐야 한다 — 종결된 사건과 오타는 할 일이
완전히 다르다. 올린 사건이 전부 결과에 있어야 대사가 된다.

`특이사항` 칼럼이 실무에서 필터를 거는 칼럼이다: 명세서 미공개 / 인수권리 있음 / 대항력 임차인 N명 /
조세채권 N건 / 회생·파산 / 항고 / 집행정지 / 유찰 N회 / 감정 N년 경과 / 용도 매칭 실패 /
임차인 매물구분 불명 / 법원 중복.

### ⚠ 세로로 더하지 말 것
한 사건에 매물이 여럿이면 **우리 채권액을 매물마다 그대로 적용**한다(매물별 시나리오라서).
회수액 칼럼을 세로로 합치면 같은 채권을 여러 번 세게 된다. 해당 행의 `특이사항`에 못 박아 뒀다.

### 한 번에 200건
법원 서버에 대한 예의이자 한 탭에서 도는 시간의 한계다(건당 3~8초, 동시 3건). 넘으면 거부하고
파일을 나누라고 안내한다. 중간에 **중지**해도 그때까지 받은 건으로 파일이 만들어진다.

### 메모리
수백 건을 한 브라우저 탭에서 돌린다. 규칙 넷(`src/caseSheet.js` 머리말에도 적어뒀다):
1. 업로드 워크북은 사건번호만 뽑고 즉시 버린다. 스타일·수식·날짜 변환을 다 끄고 읽는다.
2. 시트를 `sheet_to_json` 으로 펼치지 않는다 — 행마다 객체를 만들면 키 문자열이 행 수만큼 복제된다.
   필요한 칸만 주소로 집어 읽는다.
3. 조회 응답(명세서 비고·감정평가 요점까지 달려 무겁다)은 **한 건씩 행으로 접고 즉시 버린다**.
   전부 모아뒀다 마지막에 변환하면 원본과 변환 결과를 동시에 들게 된다.
4. 출력 행은 객체가 아니라 **배열**이다. 셀 스타일도 미리 만들어 참조만 공유한다.

낙찰가율은 `(시도·시군구·기간)` 으로 캐시한다. 같은 구의 사건이 수십 건 몰리는 게 보통이라,
이게 없으면 같은 답을 받으려고 사건 수만큼 매각통계를 다시 부른다.

### 틀고정은 없다
`xlsx-js-style` 0.18.5 쓰기 경로에 pane 관련 코드가 아예 없어서 `!views`/`!freeze` 를 넣어도
파일에 안 들어간다(라이브러리·출력 XML 양쪽 확인). 대신 자동필터를 걸어뒀다.

### ⚠ 검색 결과는 전 페이지를 받아야 한다
`dlt_srchResult` 는 한 페이지 40줄이다. 1페이지만 읽으면 목적물이 많은 사건이 조용히 잘려
감정가 합·면적·목적물 수가 전부 과소집계된다.

그런데 **`dma_pageInfo.totalCnt` 는 그냥 보내준 값을 되돌려준다** — `totalYn: "N"` 으로 물으면
서버가 세지 않는다. 1페이지에서 "N"을 보내면 `totalCnt: "0"` 이 와서 '다 받았다'고 착각한다.
**항상 `totalYn: "Y"`** 로 물어야 진짜 건수가 실려 온다.

> 실측: 2018타경6939(목적물 34건)을 pageSize 10으로 받으면 "N"일 때 10줄에서 멈추고,
> "Y"로 바꾸면 34줄을 다 받아 pageSize 40 결과(면적 4,717㎡ · 감정 77.88억)와 정확히 일치한다.

### ⚠ 같은 사건번호가 여러 법원에 있을 수 있다
사건번호의 연도·일련번호는 법원별로 따로 돌아간다. 법원코드 없이 검색하므로 두 법원 사건이
섞여 올 수 있다. 응답의 `boCd` 가 둘 이상이면 `courtConflict: true` 로 알린다(화면은 경고,
엑셀은 `특이사항`). 합쳐서 계산하지 말 것.
- `src/courtCodes.js` — 시군구 이름 → 법원 코드 해석 + 합산 로직.
- `src/statsModel.js` — 용도 위계(단일/세부/소계/전체) 판정 + 물건↔통계 용도명 매핑(`matchUsageRow`).
  경매물건은 `연립주택,다세대,빌라`, 통계는 `연립주택,다세대`라 그대로 매칭하면 '전체'로 떨어진다.
  그룹 기준은 응답의 `header`("단독주택,다가구주택")를 1순위로 쓴다. 코드 필드(`lclAuctnGdsUsgCd`)는
  세부용도마다 값이 달라(11/111/1111) 그룹이 안 묶이고, 소계가 홀로 떨어져 라벨이 "소계 소계"가 된다.
- `src/backtrack.js` — 월별 버킷 누적 + 모든 (시작월, 종료월) 구간 탐색.
  대분류 키는 `header`를 그대로 쓴다(고정 목록으로 박으면 전국 조회의 자동차·선박 등이 누락된다).

## ⚠ 시군구 코드는 법정동 코드와 다르다
법원 매각통계의 `adongSggCd`는 **1990년대 개편 이전 코드가 남아 있어** 현행 법정동 코드 뒤 3자리와 어긋난다.
그대로 보내면 **0건**이 돌아온다(2026-08 실측).

| 시군구 | 법정동 | 법원 실제 코드 |
|---|---|---|
| 서울 광진구 | 11215 | **210** |
| 서울 강북구 | 11305 | **300** |
| 서울 금천구 | 11545 | **540** |
| 인천 부평구 | 28237 | **240** |
| 인천 계양구 | 28245 | **250** |
| 광주 남구 | 29155 | **150** |
| 고양시 덕양구 | 41281 | **471** |
| 경기 이천시 | 41500 | **530** |

반대로 **한 구의 데이터가 두 코드에 나뉜 곳**도 있다(인천 연수구 185·180, 파주시 480·510, 강릉시 150·85A).
한쪽만 보면 절반이 사라진다.

**해결**: 코드를 하드코딩하지 않고 `selectAdong` 목록에서 **이름이 같은 코드를 전부** 찾아 모두 조회한 뒤 합산한다.
매각가율은 금액가중(매각가합÷감정가합)으로 재계산하며, 목록을 못 받으면 기존처럼 법정동 뒤 3자리로 폴백한다.
합산이 일어나면 조회 상태줄에 `법원코드 540+545 합산`으로 표시된다.

## 비고

- 법원 시군구 목록에는 `테스트구` 같은 시험용 항목과 폐지된 옛 행정구역(고양군·미금시 등)이 섞여 있다.
  테스트구만 걸러내고 옛 행정구역은 남긴다(그 시절 데이터가 실제로 들어 있음).
